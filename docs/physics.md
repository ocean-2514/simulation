# 二维物理模块

物理模块用于学习和验证常见的二维刚体算法。它包括刚体状态积分、宽相和窄相碰撞、接触求解、用户约束以及力生成器。

## 数据与坐标约定

- 物理位置使用 `glm::vec2`，角度使用弧度并按逆时针为正。项目没有固定长度单位；场景长度和重力数值使用同一套任意单位。
- `Transform2D` 表示形状局部坐标到世界坐标的平移和旋转。多边形顶点保存在局部空间，`WorldPoint` 与 `LocalPoint` 用于坐标转换。
- 多边形顶点按逆时针排列，`PopulateNormals` 生成对应的外法线。当前 SAT 和裁剪均以凸多边形为前提。
- `Collider` 从多边形顶点计算局部质心。刚体变换保存形状原点；施加冲量与计算角速度时，求解器使用变换后的质心及接触点相对质心的力臂。
- `CollisionManifold.normal` 始终从 body A 指向 body B。每个点的 `separation` 为正表示间隔，零表示接触，负值表示穿透。

`PhysicsWorld::gravity` 默认是 `(0, -1)`，使用者可以按场景单位调整。默认材质参数定义在 `RigidBody` 中；演示会为球体单独设置恢复和摩擦系数。

## 已实现内容

### 刚体与碰撞体

- `MotionType::Static`：不积分位置，也不响应冲量。
- `MotionType::Kinematic`：由给定速度驱动，不受重力和力生成器影响，但可与动态刚体发生碰撞。
- `MotionType::Dynamic`：受重力、外力、扭矩和碰撞冲量影响。
- `CircleCollider` 和凸 `PolygonCollider`。多边形顶点按逆时针顺序给出，并通过 `PopulateNormals` 生成边法线。
- `RigidBody` 提供碰撞类别位和掩码位；只有双方过滤条件都允许时才会创建接触。

### 碰撞检测

| 碰撞对 | 当前方法 | 接触点数 |
|---|---|---:|
| 圆形 - 圆形 | 圆心距离与半径 | 1 |
| 圆形 - 凸多边形 | 圆心到多边形边/顶点的最近点，并处理圆心位于多边形内部的情况 | 1 |
| 凸多边形 - 凸多边形 | SAT 分离轴检测，选择参考面和入射边，再裁剪入射边 | 最多 2 |

接触流形保存 A 指向 B 的法线、每点的分离量、世界接触位置、两个刚体各自的局部锚点和特征 ID。特征 ID 用于跨子步匹配接触点。

宽相由 `BVHTree2D` 维护 AABB 动态树，减少需要执行窄相检测的刚体对。BVH 只提供候选对；实际碰撞由 `CollisionDetector` 判断。

### BVH 动态树

`BVHTree2D` 的叶节点同时保存物体的 tight AABB 和用于树结构的 fat AABB。创建或移动代理时，会给 tight bounds 增加固定 margin；只要新 tight bounds 仍处于 fat bounds 内，就只更新叶节点的 tight bounds，不重插节点。物体移出 fat bounds 后才重新插入。

插入时使用 AABB 表面积代价寻找兄弟节点，内部节点 bounds 由子节点合并得到；更新路径上执行高度检查和树旋转，控制树形退化。查询先用内部 fat bounds 剪枝，命中叶节点后再用 tight bounds 做精确 AABB 检查。`ProxyId` 包含节点索引和 generation，防止已释放节点被旧代理句柄误用。

BVH 当前负责对象候选查询，不生成碰撞接触、不处理碰撞组，也不负责刚体生命周期。

### 窄相算法

**圆 - 圆：** 比较圆心距离平方与半径和的平方，避免在判定前做平方根。碰撞后由圆心连线确定法线，并计算两个圆各自的表面锚点；接触求解位置取两个表面点的中点。

**圆 - 凸多边形：** 遍历边，计算圆心到线段的最近点并记录最近边。对圆心在多边形内的情况，使用最近边确定推出方向；对外部情况，检查最近距离是否小于圆半径。结果输出圆与多边形各自的局部表面锚点。

**凸多边形 - 凸多边形：** 在两多边形的边法线轴上执行 SAT。任何分离轴都表示无碰撞；否则选择分离距离最大的有效面作为参考面。另一形状中法线最反向的边作为入射边，然后通过参考面的两条侧边界裁剪。裁剪后最多保留两个落在接触容差内的点。特征 ID 记录参考侧、参考面、入射面、入射顶点或裁剪侧，用于缓存匹配。

这类 clipping 算法依赖凸性和有序边法线。当前没有凹多边形三角化/凸分解，也没有一般凸体 GJK/EPA。

### 接触和约束求解

`ContactConstraint` 为流形中的每个点维护独立的法向和切向累积冲量、有效质量和恢复目标。速度阶段使用顺序冲量迭代，法向冲量不允许拉力，摩擦冲量限制在由摩擦系数和法向冲量决定的区间内。位置阶段重新计算局部锚点的世界位置和剩余穿透量。

`ContactCache` 按刚体对和接触特征保存上一子步的冲量。匹配成功时会按时间步比例恢复冲量；法线变化过大或缓存过期时丢弃旧值。接触约束本身每个子步重新生成，跨子步保留的是冲量缓存。

缓存键由有序的 `BodyId` 对与 `ContactFeatureId` 组成，不使用浮点接触坐标作为键。缓存中保存单位法线、法向/切向冲量、上次时间步和最近匹配的子步序号。恢复时要求新旧法线点积不小于 `0.9`；冲量按新旧 `deltaTime` 比例缩放，并将比例限制在 `[0.5, 2.0]`。缓存未匹配超过 3 个子步后清除。切向缓存还会在恢复后按当前法向冲量和摩擦系数重新夹紧。

缓存只复用速度阶段的冲量，不缓存位置修正量。若接触特征变化或法线变化明显，缓存失效是预期行为；它不会将旧的世界坐标接触点强行套到新流形上。

用户约束实现于 `engine/src/Physics/Constraints/`：

- `DistanceConstraint`：约束两个局部锚点之间的距离。
- `FixedConstraint`：约束相对位置和角度。
- `HingeConstraint`：约束两个锚点重合，同时保留相对转动自由度。

`ForceGenerator` 与约束分开。当前 `SpringForceGenerator` 在两个锚点之间计算弹簧力和沿弹簧方向的阻尼力。

### 各约束的求解方式

- **距离约束：** 在两个局部锚点之间建立一个标量长度约束，沿锚点连线计算有效质量与速度偏差；当前实现是双向约束，累积冲量不限制正负，可表示拉伸或压缩的固定长度连杆。
- **固定约束：** 将两个锚点的位置重合，并将相对角度保持在创建时的参考角度。线性锚点误差和角误差分别求解，因此具备二维刚性焊接的效果。
- **铰链约束：** 只要求两个锚点重合，使用 2×2 线性有效质量矩阵同时处理 x/y 方向耦合，不添加相对角约束，所以物体仍可绕铰链转动。
- **弹簧力生成器：** 在锚点间按 Hooke 弹簧项 `k * (length - restLength)` 与沿轴阻尼项计算力，并对偏心锚点产生扭矩。它是显式力，不是刚性距离约束，结果会受刚度和时间步影响。

距离、固定和铰链约束的累积冲量保存在约束对象上，并在后续子步按时间步比例 warm start；与之不同，接触约束每个子步重新创建，因此由独立的 `ContactCache` 保留跨步数据。

## 数值求解流程

一个物理子步先应用力并积分刚体变换，再检测接触。随后接触和用户约束在同一迭代循环中交替求解速度，最后交替进行位置修正。接触冲量的累积用于当前子步内的多轮迭代；缓存提供下一子步的 warm start 初值。

当前代码将速度迭代和位置迭代都设为 5 轮。它们与 `PhysicsWorld::Step` 的子步数分别控制不同误差来源：增加子步可以缩短每次积分的时间跨度，增加求解轮数可以改善同一子步内约束的收敛。

### 冲量求解的基本形式

对接触法线 `n`，设两个接触力臂为 `rA`、`rB`，刚体质量倒数为 `invMass`，转动惯量倒数为 `invInertia`，法向有效质量的倒数为：

```text
kN = invMassA + invMassB
   + invInertiaA * cross(rA, n)^2
   + invInertiaB * cross(rB, n)^2
normalEffectiveMass = 1 / kN
```

每轮求解先根据当前接触点相对速度更新累积法向冲量，再将总冲量投影到非负范围，只对新旧累积量之差施加冲量。切向方向使用相同的有效质量思路，并把累积切向冲量限制在 `[-friction * normalImpulse, +friction * normalImpulse]`。当前接触摩擦使用两刚体摩擦系数的几何平均，恢复系数使用两者中的较小值；低速接触不会触发恢复。

位置修正不重复使用检测时的单一穿透标量。每轮会将每个接触点的局部锚点变换回世界空间，重新计算剩余分离量和当前力臂，再按 Baumgarte 系数修正部分误差。默认 `slop = 0.005`、`baumgarte = 0.2`。多边形参考面法线会跟随参考刚体旋转；圆-圆的两个局部锚点分别绑定两侧表面，保证锚点间距能表达真实穿透量。

### 最小使用示例

以下代码展示物理世界中创建动态圆形刚体的基本 API；渲染不是创建物理刚体的必要条件：

```cpp
#include "Physics/PhysicsWorld.hpp"

PhysicsWorld world;
world.gravity = {0.0f, -9.8f};

RigidBody body;
body.motionType = MotionType::Dynamic;
body.SetMass(1.0f);
body.friction = 0.5f;
body.restitution = 0.1f;

Collider collider{ColliderData{CircleCollider{0.5f}}};
const BodyId ball = world.CreateBody(body, collider, {0.0f, 2.0f});

// 在应用循环中推进模拟；第二个参数是物理子步数。
world.Step(1.0f / 60.0f, 5);
```

创建多边形时，应先填入逆时针局部顶点并调用 `PolygonCollider::PopulateNormals()`，再构造 `Collider`。要将刚体显示在当前 OpenGL 应用中，可以使用演示层的 `ShapeProxy`；这个代理不是物理计算必需的。

### 碰撞过滤

过滤发生在 BVH 候选对生成之后、窄相之前。A 和 B 只有在双方都允许时才继续：

```text
(A.categoryBits & B.maskBits) != 0
&& (B.categoryBits & A.maskBits) != 0
```

类别描述对象所属组，掩码描述对象愿意与哪些组碰撞。当前 API 将这些位保存在 `RigidBody` 上，并跳过过滤失败的窄相检测和接触创建。

## 已知范围与限制

- 碰撞形状限于圆形和凸多边形；凹形状需要由调用方拆分为凸形状。
- 没有连续碰撞检测。高速物体仍可能在离散时间步之间穿过薄物体。
- 多接触法向冲量目前逐点顺序求解，没有双点块求解器；复杂堆叠会受迭代次数、时间步和碰撞顺序影响。
- 位置修正是近似方法，不是严格的几何投影；大穿透和极端参数需要专门处理。
- 没有睡眠、刚体岛、并行求解或自动化物理回归测试。
- 当前没有 3D 刚体、布料、软体或流体模拟实现。

这些限制属于当前实现范围，不能用演示画面替代算法验证。修改碰撞或求解代码时，建议增加小而可重复的数值场景，并记录穿透深度、接触点数量、关节锚点误差和性能数据。
